# Porting a Plugin to wadspa

There are four common paths depending on what kind of plugin you're porting:

- **SWH LADSPA plugin** — use the automated bulk-build pipeline (`scripts/build-all.js`)
- **Custom LADSPA plugin** — use `wadspa build` directly
- **Pure C/C++ LV2 plugin** — use `wadspa build-lv2` with `scripts/auto-setup.js`
- **Qt-dependent LV2 plugin** — wire `toolchain/qt-stub/` and write a setup script

---

## Path 1: SWH LADSPA plugin (automated)

The [Steve Harris SWH collection](https://github.com/swh/ladspa) is already wired into the build pipeline. Adding a plugin takes one manifest entry and one command.

### 1. Add an entry to `plugins/manifest.json`

```json
{
  "id": "my_plugin",
  "xml": "my_plugin_1234.xml",
  "npmName": "@wadspa/my-plugin"
}
```

Fields:

| Field | Required | Description |
|-------|----------|-------------|
| `id` | yes | Directory name under `plugins/` |
| `xml` | yes | XML filename in `swh-plugins/` |
| `npmName` | yes | npm package name |
| `util` | no | Header files to copy from `plugins/shared/util/` (e.g. `["biquad.h"]`) |
| `utilSrc` | no | C source files to compile from `plugins/shared/util/` (e.g. `["db.c","rms.c"]`) |

### 2. Run the build script

```sh
node scripts/build-all.js --only my_plugin
```

The script handles everything automatically:
- Generates C source from the XML descriptor via `makestub.pl`
- Copies `ladspa.h`, `ladspa-util.h`, and `config.h` from `plugins/shared/`
- Runs `wadspa build` with the right flags
- Writes the compiled package to `plugins/<id>/dist/`

### Common `util` dependencies

| Plugin type | `util` | `utilSrc` |
|-------------|--------|-----------|
| Filters / EQ | `["biquad.h"]` | — |
| Compressor / dynamics | `["db.h","rms.h"]` | `["db.c","rms.c"]` |
| Waveguide / physical | `["waveguide_nl.h"]` | — |

## Path 2: Custom LADSPA plugin

For plugins not in the SWH collection — third-party C code, original effects, etc.

### 1. Create the plugin directory

```
plugins/my_plugin/
  my_plugin.c       LADSPA plugin source
  ladspa.h          copy from plugins/shared/ladspa.h
  config.h          copy from plugins/shared/config.h (if needed)
```

### 2. Build

```sh
wadspa build plugins/my_plugin --name @wadspa/my-plugin
```

The toolchain:
1. Loads the compiled `.so` natively to inspect ports
2. Generates a C shim exposing `shim_init`, `shim_run`, and typed getters/setters
3. Compiles the plugin + shim with `emcc` to `.js` + `.wasm`
4. Writes `dist/` with `index.js`, `processor.js`, `package.json`

## Path 3: Pure C/C++ LV2 plugin (auto-setup)

For LV2 plugins with no heavy external dependencies (no Qt, no libsndfile, no libGL). The `auto-setup.js` script handles source discovery and iterative compilation automatically.

### 1. Add to `sources.json`

```json
{
  "id": "my-plugin",
  "git": "https://github.com/author/my-plugin.git",
  "setup": null,
  "description": "Brief description"
}
```

Setting `"setup": null` tells `setup-all.js` to use the generic `auto-setup.js` fallback.

### 2. Clone and run setup

```sh
node scripts/fetch-sources.js --only my-plugin
node scripts/setup-all.js --only my-plugin
```

`auto-setup.js` will:
1. Find all `manifest.ttl` (or `manifest.ttl.in`) files in the repo
2. Discover source files from the bundle directory, `CMakeLists.txt`, and `Makefile`
3. Check for Qt headers — if found, adds `toolchain/qt-stub` automatically
4. Attempt compilation, then apply fixes for common errors (missing headers → add include dir)
5. On success, write the compiled WASM to `plugins/<id>/dist/` and add an entry to `plugins/lv2.json`

### 3. Build

```sh
node scripts/build-instruments.js --only my-plugin
```

You can also invoke `auto-setup.js` directly on any local directory:

```sh
node scripts/auto-setup.js path/to/repo --id my-plugin
node scripts/auto-setup.js path/to/repo --id my-plugin --dry-run   # print plan only
node scripts/auto-setup.js path/to/repo --bundle src/my.lv2        # specify bundle dir
```

### What auto-setup handles

- `.ttl.in` template files (replaces `@LIB_EXT@` and similar placeholders)
- Qt detection: greps all `.c`, `.cpp`, `.h`, `.hpp` for `#include <Q...>` or `#include "Q..."`
- Include path expansion: adds all subdirectories of the repo root that contain headers
- Iterative error recovery: on each compile failure, searches the repo for missing headers and adds their directories

### When auto-setup isn't enough

If the plugin has heavy external dependencies (libsndfile, pthreads with real blocking, OpenGL, etc.) or its source files depend on a `config.h` generated by CMake/Autotools, you'll need a custom setup script (Path 4).

## Path 4: Qt-dependent LV2 plugin

Many high-quality Linux synthesizers (rncbc's suite: synthv1, drumkv1, padthv1) use Qt for their DSP configuration layer — `QSettings` for preset I/O, `QMap`/`QHash` for parameter tables, `QDomDocument` for XML presets. The `toolchain/qt-stub/` directory provides header-only C++ replacements for all of these, backed by `std::` containers, with no Qt installation required.

### What's in `toolchain/qt-stub/`

| Header | Provides |
|--------|----------|
| `qglobal.h` | `Q_OBJECT`, signal/slot macros, `QChar`, `Qt::` namespace enums, `qDeleteAll`, math helpers |
| `QString` | `std::string` wrapper with full Qt string API (`arg()`, `split()`, `number()`, etc.) |
| `QStringList` | `std::vector<QString>` with Qt list API and Java-style iterators |
| `QMap` | `std::map` wrapper with Qt iterator API (`.key()`, `.value()`, `Iterator`/`ConstIterator`) |
| `QHash` | `std::unordered_map` wrapper with Qt API |
| `QSet` | `std::set` wrapper |
| `QVariant` | Type-erased value with `toString()`, `toInt()`, `toStringList()`, etc. |
| `QSettings` | Inheritable no-op settings class (WASM has no persistent storage) |
| `QDomDocument` | XML DOM stub — all operations are no-ops, returns empty nodes |
| `QFile` / `QFileInfo` / `QDir` | File I/O stubs (no-op; WASM has no filesystem by default) |
| `QMutex` / `QThread` | Threading stubs (no-op; WASM is single-threaded) |
| `QAtomicInt` | Non-atomic int wrapper (WASM is single-threaded) |
| `QSharedPointer` / `QScopedPointer` | `std::shared_ptr` / `std::unique_ptr` wrappers |
| `QObject` | Base class stub with virtual destructor and no-op signals |
| `QApplication` | `Qt::ApplicationAttribute` enum + no-op `setAttribute` |
| `fftw3.h` | HC2R inverse DFT stub for PADsynth wavetable generation |

### 1. Add `toolchain/qt-stub` to the lv2.json entry

```json
{
  "id": "my-qt-synth",
  "description": "...",
  "category": "Instruments",
  "includes": ["toolchain/qt-stub"],
  "sources": ["my_synth.cpp", "my_synth_lv2.cpp", "my_synth_sched_wasm.cpp"]
}
```

The build script resolves `"toolchain/qt-stub"` relative to the repo root.

### 2. Replace QThread-based schedulers

Most rncbc-style plugins use a `QThread` worker for deferred processing. Since WASM is single-threaded, replace the scheduler with a synchronous version: all scheduled work executes inline when `schedule()` is called.

See `plugins/drumkv1/drumkv1_sched_wasm.cpp` and `plugins/padthv1/padthv1_sched_wasm.cpp` for reference implementations. The pattern:

```cpp
void MySynth_sched::schedule(int sid)
{
    // enqueue
    const uint32_t w = (m_iwrite + 1) & m_nmask;
    if (w != m_iread) { m_items[m_iwrite] = sid; m_iwrite = w; }
    // execute inline — no thread needed
    sync_process();
}
```

### 3. Replace file-loading dependencies

- **libsndfile** (audio sample files) — replace `*_sample.cpp` with a stub that generates synthetic audio. See `plugins/drumkv1/drumkv1_sample_stub.cpp` for a white-noise burst generator.
- **FFTW3** (PADsynth wavetable generation) — `toolchain/qt-stub/fftw3.h` provides a correct O(N²) HC2R inverse DFT. It's slow at init time but correct.

### 4. Generate config.h

rncbc plugins expect a `config.h` with feature flags. Generate it in your setup script:

```js
writeFileSync(join(OUT, 'config.h'), `\
#pragma once
#define CONFIG_LV2 1
#define CONFIG_LV2_ATOM_FORGE_OBJECT 1
#define CONFIG_LV2_ATOM_FORGE_KEY    1
/* #undef CONFIG_LV2_OLD_HEADERS */
#define PROJECT_NAME    "my-synth"
#define PROJECT_DOMAIN  "my-synth.example.com"
#define PROJECT_VERSION "1.0.0"
`);
```

### 5. Write a setup script

Follow the pattern in `scripts/setup-drumkv1.js` or `scripts/setup-padthv1.js`:

```js
// scripts/setup-my-synth.js
import { copyFileSync, mkdirSync, writeFileSync, existsSync } from 'fs';
import { join, dirname } from 'path';
import { fileURLToPath } from 'url';

const ROOT = join(dirname(fileURLToPath(import.meta.url)), '..');
const SRC  = join(ROOT, 'my-synth', 'src');
const OUT  = join(ROOT, 'plugins', 'my-synth');

mkdirSync(OUT, { recursive: true });

// 1. Copy DSP sources (exclude UI, jack, standalone files)
for (const f of ['my_synth.cpp', 'my_synth_param.cpp', 'my_synth_lv2.cpp']) {
    copyFileSync(join(SRC, f), join(OUT, f));
}
// 2. Copy TTL files
copyFileSync(join(SRC, 'my-synth.lv2/manifest.ttl'), join(OUT, 'manifest.ttl'));
copyFileSync(join(SRC, 'my-synth.lv2/my_synth.ttl'), join(OUT, 'my_synth.ttl'));
// 3. Generate stubs
writeFileSync(join(OUT, 'config.h'), `/* ... */`);
writeFileSync(join(OUT, 'my_synth_sched_wasm.cpp'), `/* synchronous scheduler */`);
// 4. Register in lv2.json
// (see setup-drumkv1.js for the registry update pattern)
```

Register the script in `setup-all.js`:
```js
const SETUPS = {
  // ...
  'my-synth': 'setup-my-synth.js',
};
```

## Shared headers (`plugins/shared/`)

All canonical LADSPA headers live here. Never edit them inside individual plugin directories — patch `plugins/shared/` instead.

| File | Notes |
|------|-------|
| `ladspa.h` | Standard LADSPA API |
| `ladspa-util.h` | SWH utility macros |
| `config.h` | Autotools stub (empty, WASM is always little-endian) |
| `util/biquad.h` | Fully patched — all float literals replaced with double |
| `util/iir.h/c` | IIR filter implementation |
| `util/rms.h/c` | RMS envelope follower |
| `util/db.h/c` | dB conversion utilities |
| `util/buffer.h/c` | Ring buffer |
| `util/waveguide_nl.h` | Nonlinear waveguide |

The biquad patch (`double` literals throughout) prevents catastrophic cancellation at low frequencies. The toolchain also passes `-DBIQUAD_TYPE=double` automatically.

## Troubleshooting

**`emcc: requires python 3.10 or above`** — a Python virtualenv with an older Python is active. Deactivate it before building.

**`ladspa_descriptor returned NULL`** — your plugin must export `ladspa_descriptor(0)` and return a valid descriptor at index 0.

**`'SomeHeader.h' file not found`** — add the directory containing that header to the `includes` array in `lv2.json`, or run `auto-setup.js` which searches the repo automatically.

**`QMap::value()` / `constBegin()` missing** — you're using a Qt class without the qt-stub. Add `"includes": ["toolchain/qt-stub"]` to `lv2.json`.

**`std::hash<QString>` not defined** — included in `toolchain/qt-stub/QString` as a `std::hash<>` specialization; ensure qt-stub comes before any Qt header in the include path.

**Plugin sounds wrong at low frequencies** — float precision in biquad. Confirm you're using the `biquad.h` from `plugins/shared/util/` (already patched) and not a fresh copy from the SWH repo.

**LV2 port count is wrong** — the TTL parser matches all `[...]` blocks in the `.ttl` file. Make sure each port block contains `lv2:index`, `lv2:symbol`, and a direction/type triple.

**Stuck notes (LV2 synth)** — if rapid re-clicks cause notes to sustain, check that `note_on` retriggers an existing voice for that MIDI note before allocating a new one. See `plugins/wadspa_synth/wadspa_synth.c` for the reference implementation.

## Porting checklist

**LADSPA (SWH)**
- [ ] Entry added to `plugins/manifest.json`
- [ ] `util` / `utilSrc` fields set for any external headers
- [ ] `node scripts/build-all.js --only <id>` succeeds
- [ ] Plugin tested in browser (Chrome + Safari)

**LADSPA (custom)**
- [ ] `ladspa_descriptor(0)` exported and returns a valid descriptor
- [ ] All headers reachable from the build dir
- [ ] `wadspa build` succeeds and port list looks correct
- [ ] Plugin tested in browser

**LV2 (pure C/C++)**
- [ ] Entry added to `sources.json` (or `plugins/lv2.json` directly)
- [ ] `manifest.ttl` and plugin `.ttl` present and parseable
- [ ] All ports have `lv2:index`, `lv2:symbol`, direction, and type
- [ ] `node scripts/auto-setup.js` or `wadspa build-lv2` succeeds
- [ ] MIDI input or audio input path tested in browser

**LV2 (Qt-dependent)**
- [ ] `"includes": ["toolchain/qt-stub"]` in `lv2.json`
- [ ] QThread scheduler replaced with synchronous WASM version
- [ ] File-loading dependencies (libsndfile, etc.) replaced with stubs
- [ ] `config.h` generated with correct feature flags
- [ ] `node scripts/setup-<id>.js` idempotent (safe to re-run)
- [ ] `node scripts/build-instruments.js --only <id>` succeeds
- [ ] Plugin tested in browser (Chrome + Safari)
